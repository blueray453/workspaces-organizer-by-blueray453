**Status:** Planned, not executed.
**Scope:** Merge the entire `gnome-utils` extension into `workspaces-organizer`. Keep `keybindings-by-blueray453` separate but update its command strings.
**Outcome:** Two extensions total (`workspaces-organizer`, `keybindings-by-blueray453`), one bus name, one CLI. `gnome-utils` directory deleted.

## 6. MRU contract

Codified at the top of `workspaceActions.js`:

> Every function that mutates Mutter's MRU ends with `Mru`:
> - `navigateToWindowMru(win)` — unminimize + switch ws + focus
> - `raiseAndMakeRecentMru(win)` — raise + recency bump (no focus)
> - `activateWorkspaceWithFocusMru(ws, win)` — switch ws + focus
>
> Functions without the suffix are MRU-neutral:
> - `peekWindow(win, opts)` — clone preview, no focus, no recency
> - `stopPeek(immediate)`
> - `moveWindowsToWorkspace(wins, ws)` — `change_workspace` per window
> - `scrollModelWindows(dir)`, `cycleWindowsOnWorkspace(i, dir)` — delegate
>
> Rule of thumb:
> - User click / Enter / hotkey → **commit** (`Mru`)
> - User hover / navigate / browse → **peek**
> - Script layout op → **peek**
> - Script "bring this forward" → **commit**

`grep -rn 'Mru(' lib/` finds every MRU mutation in the extension.

### 6.1 `activate(0)` vs `unminimize()` vs `navigateToWindowMru`

| Call | Effect | Use for |
|---|---|---|
| `win.unminimize()` | Clear minimized flag. MRU-neutral. | Layout ops after unmaximize; script primitives that need the window unminimized but not focused. |
| `win.activate(0)` | Unminimize + raise + make-recent + focus. **MRU-mutating.** | **Never called directly outside `navigateToWindowMru`.** |
| `navigateToWindowMru(win)` | Wraps activate/activate_with_focus with sticky-window-correct branch. | Every user gesture. |
| `peekWindow(win)` | Clone preview via `peekController`. MRU-neutral. | Hover, browse, external-drag row preview, script layout op. |

### 6.2 Peek vs commit sites (post-migration)

**Commit (`navigateToWindowMru`):** panel scroll, workspace cycle, overlay Enter/click, flyout row click, group icon click, panel window-icon click, context-menu Activate, external drag drop commit, `WindowActivateGivenWinID`, `WindowFullScreenGivenWinID`, `WindowMaximizeGivenWinID`, `WindowsActivateGivenWMClass`, `ToggleWindowsCurrentWorkspace`.

**Peek (`peekWindow`):** overlay selection change, flyout row hover, Ctrl+hover on window icon, external-drag row hover, group icon Ctrl+motion, group icon hover *(new)*, `WindowResizeGivenWinID`, `WindowMoveResizeGivenWinID`.

## 7. `located_on_workspace` / `showing_on_its_workspace` sweeps

Two APIs, two questions, orthogonal:

| API | Answers |
|---|---|
| `win.located_on_workspace(ws)` | "Is this window assigned to ws?" — **TRUE for sticky windows on every workspace** |
| `win.showing_on_its_workspace()` | "Would this window draw if we looked at its workspace?" — **FALSE for minimized / unmapped / shaded / unmanaging** |

Substitution rules:

- **Filtering a list to a workspace** → `located_on_workspace(ws)`. Never `get_workspace() === ws` (wrong for sticky).
- **"Would this draw right now"** → `showing_on_its_workspace()`. Never `!win.minimized` (misses unmapped/restacking/shaded).
- **"Is this window's stored workspace X"** → `get_workspace() === ws` — only legitimate when you need to *switch* to that workspace, not when filtering.

- **Sticky window (always-on-top):** appears under every workspace filter in the overlay; clicking its panel icon from a non-owning workspace focuses in place; `<Super>s` then workspace switch keeps the border visible.
- **Group icon hover:** after `flyout-dwell-ms`, the MRU window of the group appears as a centered peek (no MRU change). 40% later the flyout opens. Click a row — window is focused via `navigateToWindowMru`.
- **External drag:** dropping a file onto a workspace thumbnail activates the workspace; no spurious settle animation for windows already there.
- **Title-bar drag:** dragging a window over a workspace thumbnail moves it; unaffected windows keep their MRU positions.
- **`<Super>grave`:** nothing happens (version-2 migration reset `kb-1`).

## 13. What is deliberately NOT happening

- **No interface consolidation.** Five interfaces, one bus.
- **No renaming of methods.** Every surviving method name is identical to its `gnome-utils` predecessor.
- **No change to `prefs.js` or schemas** in either extension.
- **No change to `gdmenu`.** Different mechanism (`Selected` / `Cancelled` signals), different script.
- **No change to `extension.js`** in `workspaces-organizer` — `DBusService.initDBusService()` / `installCli(this.path)` are the only two references to D-Bus.
- **No `-i` flag** in the new CLI. Method names are globally unique today; if two ever collide, the CLI errors with "ambiguous" and demands nothing — you'd rename the method.
- **No `dbusClient.js` in `workspaces-organizer`.** `keybindingFunctions.js` no longer needs it; `keybindings-by-blueray453/dbusClient.js` survives for its own Super-key override.

## 14. Open items (decide before executing)

1. **`WindowResizeGivenWinID` / `WindowMoveResizeGivenWinID`** — currently the plan uses `peekWindow` (MRU-neutral). If any script *depends* on resize stealing focus, change to `navigateToWindowMru`. Default: peek.
2. **`kb-1` `<Super>grave`** — retired. If you want `<Super>grave` bound to something else (e.g. `ToggleAllWindows`), add a `kb-1` entry with the new command but do **not** bump `KEYBINDINGS_VERSION` — the command string is read from code on every press.
3. **`WindowFullScreenGivenWinID`** — plan changes `win.maximize(3)` to `win.make_fullscreen()`. If any caller depends on the accidental maximize semantics, keep `maximize(3)`. Default: fix the bug.
4. **Sticky-window behaviour changes** — the `located_on_workspace` sweeps change click semantics for sticky windows (focus in place rather than workspace switch). Verify no script or user workflow depended on the old jump behaviour.
